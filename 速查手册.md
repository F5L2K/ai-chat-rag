# 项目速查手册

> RAG 知识库问答：上传文档 → 切块向量化 → 混合检索 + 精排 → DeepSeek 流式回答带引用。



***

## 一、一句话定位

本地跑的开卷考试式问答系统。文档上传后切块向量化；提问时向量 + BM25 双路召回、Cross-encoder 精排、RRF 融合取 top3 拼进 prompt，让 DeepSeek 照着片段答，答案带章节级引用。



***

## 二、两条主干流程图

### 入库流



```
文件(bytes)
  → parsing/ 按扩展名分发 → list[Block]{text,page_no,section_path,kind}
  → chunking.build_chunks → list[Chunk]{500字/块,重叠50,带char偏移}
  → embeddings.get_embeddings (bge-small-zh-v1.5)
  → documents.index_document:
       ① sha256 查重
       ② SQLite: INSERT documents + chunks（一个事务）
       ③ FAISS: add_documents(chunk_id=doc_id:i)
       ④ save_local 落盘
       ⑤ bm25.mark_dirty()
```

### 问答流



```
问题(query)
  → rag.retrieve_relevant:
       ① FAISS similarity_search(k=20)        ← 向量粗召回
       ② rerank_documents(query, 20)          ← Cross-encoder 精排
       ③ bm25.search(query, 20)               ← BM25 字面召回
       ④ rrf_fuse([精排, BM25], k=60)[:3]    ← RRF 融合取 top3
  → rag.build_rag_prompt: top3 原文按"资料片段1/2/3"拼进 system prompt
  → llm.client.chat.completions.create(stream=True)
  → chat.py: 流式 yield 文本 → 存消息 → 末尾塞 __CITATIONS_JSON__{...}
```

## 四、关键函数速查



| 函数                                  | 在哪                  | 干什么                                         |
| ----------------------------------- | ------------------- | ------------------------------------------- |
| `retrieve_relevant(query)`          | rag.py              | 双路检索编排，返回 top3                              |
| `build_rag_prompt(query)`           | rag.py              | 检索 + 拼 prompt，返回 (prompt, citations, trace) |
| `index_document(title, parsed)`     | documents.py        | 三写：SQLite + FAISS + BM25 脏标记                |
| `update_document(doc_id, parsed)`   | documents.py        | 清旧 chunks / 向量 → 重建，version+1               |
| `delete_document(doc_id)`           | documents.py        | 三处一起清，防漂移                                   |
| `build_chunks(blocks)`              | chunking.py         | 章节感知切分，三个 flush 条件                          |
| `rerank_documents(query, docs, k)`  | rerank.py           | Cross-encoder 精排，可降级                        |
| `rrf_fuse(rank_lists, k, tiebreak)` | bm25.py             | 名次融合 `score=Σ1/(k+rank)`                    |
| `parse_document(filename, source)`  | parsing/**init**.py | 按扩展名分发                                      |

## 五、配置项（.env 可覆盖）



| 变量                   | 默认     | 作用         |
| -------------------- | ------ | ---------- |
| `DEEPSEEK_API_KEY`   | **必填** | LLM 密钥     |

| `OCR_DPI`            | 200    | OCR 渲染分辨率  |

## 七、常见报错 → 修改点位



| 现象                     | 去哪改 / 查                                          |
| ---------------------- | ------------------------------------------------ |
| `ModuleNotFoundError`  | `pip install -r requirements.txt`                |
| `未配置模型密钥`              | `.env` 里填 `DEEPSEEK_API_KEY`                     |
| 前端 "连不上后端"             | 后端没起，或端口不对（改 `--port` + frontend.py 里接口地址）       |
| 上传 `.doc`/`.xls` 报 400 | 老格式，另存为新格式（提示在 `parsing/__init__.py` 的 `_HINTS`） |
| PDF 上传后没内容             | 日志看 `needs_ocr=True`；确认装了 pymupdf + rapidocr     |
| 回答不带引用                 | 日志看 `未检索到资料` → 知识库为空或问题不相关                       |
| 回答在瞎编                  | 日志看 `检索完成` 那行命中数；命中 = 0 是检索问题，命中 > 0 是 LLM 问题    |
| 精排 / OCR 报错            | 看 warning 日志；自动降级了，不影响主流程                        |
| FAISS 维度不匹配            | 换了 embedding 模型，删 `faiss_store/` 重建              |
| 端口被占                   | `--port 8001`，同步改 frontend.py                    |

## 八、面试核心卖点（按这个顺序讲）



1. **两阶段检索**：双塔粗召回 20 个保证不漏 → Cross-encoder 精排取 top3 保证准

2. **混合检索 + RRF**：向量管语义、BM25 管字面（E102/E202 编号问题），RRF 只比名次不比分数

3. **章节级引用**：Hit@K vs SecHit@K 的差值暴露 "找对文档但引用定位丢了"

4. **可降级设计**：精排 / BM25/OCR 任何一个挂了自动退回基础版，主流程不崩

5. **消融实验**：纯向量 80% → + 精排 90% → +BM25 100%，每个模块的收益有数据

## 九、诚实清单（别吹过头）



* 没有认证、没有多租户权限（tenant\_id="default" 是占位）

* SQLite + FAISS 是单进程本地存储，生产要换 PG + Milvus

* 没有 Docker、没有日志落盘、没有文件大小限制

* 没接 ERP/OA 业务系统，采集层是文件上传

* 没做信息抽取（只有问答和摘要）
